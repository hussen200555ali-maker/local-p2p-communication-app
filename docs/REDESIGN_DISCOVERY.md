## المشكلة الحالية

### الأرقام
- **50 رسالة UDP كل 10 ثوانٍ** = 300 رسالة/دقيقة
- **5 انقطاعات TCP في 10 دقائق** بسبب إغراق الشبكة
- **1 حالة فشل PONG** بسبب عدم استقرار الاتصال

### السبب الجذري
نظام الاستكشاف الحالي يستخدم "استطلاع دوري صاخب" (Periodic Broadcast Storm):
1. `_announcementTimer` كل 10 ثوانٍ → DISCOVER broadcast
2. `_heartbeatTimer` كل 5 ثوانٍ → PING broadcast
3. `_reconnectTimer` كل 5 ثوانٍ → محاولات إعادة اتصال

هذا يخلق حلقة تغذية راجعة:
```
DISCOVER → إعادة اتصال → انقطاع → DISCOVER → إعادة اتصال → ...
```

## الحل: نظام قائم على الأحداث (Event-Driven)

### المبدأ الأساسي
**"أعلن عند الحدث، لا ت_broadcast دورياً"**

### الحدث والسلوك

| # | الحدث | السلوك | التردد |
|---|---|---|---|
| 1 | دخول المستخدم للتطبيق | إرسال 3 إعلانات USER_ONLINE (500ms بين كل واحدة) | مرة واحدة |
| 2 | خروج المستخدم من التطبيق | إرسال USER_OFFLINE واحد | مرة واحدة |
| 3 | نبض التأكيد (Keep-Alive) | USER_ONLINE واحد | كل 60 ثانية |
| 4 | زر التحديث (يدوي) | DISCOVER_REQUEST واحد | عند الطلب |
| 5 | انقطاع TCP مع صديق | لا UDP، إعادة اتصال TCP مباشرة | عند الحاجة |

## بروتوكولات الرسائل الجديدة

### USER_ONLINE
```json
{
  "type": "USER_ONLINE",
  "userId": "uuid",
  "username": "string",
  "ip": "192.168.1.x",
  "port": 8080
}
```

### USER_OFFLINE
```json
{
  "type": "USER_OFFLINE",
  "userId": "uuid"
}
```

### DISCOVER_REQUEST
```json
{
  "type": "DISCOVER_REQUEST",
  "userId": "uuid"
}
```

## إدارة حالة المستخدم

### الحالات
| الحالة | الشرط | العرض |
|--------|-------|-------|
| **متصل (Online)** | اتصال TCP حي أو USER_ONLINE خلال 70 ثانية | دائرة خضراء نابضة |
| **جارٍ التحقق (Checking)** | TCP انقطع فجأة، نحاول إعادة الاتصال | دائرة برتقالية |
| **غير متصل (Offline)** | USER_OFFLINE صريح أو 70 ثانية بدون إشارة | دائرة رمادية |

### timeout
- **70 ثانية** = 60 ثانية Keep-Alive + 10 ثوانٍ buffer

---

## إعادة الاتصال الذكية

### الخوارزمية
```
عند انقطاع TCP:
1. ضع الصديق في "جارٍ التحقق"
2. حاول إعادة الاتصال TCP مباشرة (آخر IP معروف)
3. exponential backoff: 3s → 6s → 12s
4. بعد 3 محاولات فاشلة: أرسل DISCOVER_REQUEST واحد
5. إذا فشل: أعلنه "غير متصل"
```

### قاعدة مهمة
**لا UDP أثناء إعادة الاتصال** - فقط TCP مباشر

## سيناريوهات الاختبار

| # | السيناريو | النتيجة المتوقعة |
|---|-----------|------------------|
| 1 | فتح التطبيق على جهازين | ظهور "متصل" خلال 3 ثوانٍ |
